# Обновление учебного содержания Луми

Проверка источников и файлов: 11 октября 2026 года.

## Что подготовлено

- `content/parent-articles.json`: 12 оригинальных статей для родителей, 48 разделов и 12 коротких практик. Заголовок, краткое описание, категория и время предназначены для компактной плитки. Полный текст, упражнение и источники открываются внутри статьи.
- `content/courses.json`: 6 оригинальных курсов, 24 модуля, 72 вопроса с выбором ответа и 24 практические миссии.
- Использовано 20 уникальных проверенных URL первичных организаций: исследовательских и образовательных учреждений, разработчиков и официальных ведомств.
- Не изменены `curriculum.json`, существующий каталог источников, сервер, приложение, стили и package.json.

Все сценарии, семейные реплики и тестовые задачи написаны для Луми. Материалы не являются копией курсов Google, CS Unplugged, UNESCO или другого издателя. Внешние источники поддерживают отдельные определения и общие принципы; они не удостоверяют эффективность или аккредитацию Луми.

## Статьи для родителей

- **Как говорить об ошибке** (`feedback-next-step`) - Фразы, после которых понятен следующий шаг, а достоинство ребёнка не зависит от ответа.
- **Подготовка к школе через игру** (`preschool-play`) - Счёт, речь, правила и самостоятельность в короткой игре, которую можно закончить вовремя.
- **Домашка без ежедневной борьбы** (`homework-without-battle`) - План, понятная помощь и право зафиксировать затруднение вместо бесконечного переписывания.
- **Как обсуждать навязывание взглядов** (`critical-thinking-pressure`) - Разбираем утверждения и приёмы давления без требования принять мнение взрослого.
- **Как сравнивать школьные программы** (`compare-programs`) - Смотрим на темы, навыки и способ проверки, не на обещание «единого стандарта Европы».
- **Подарки за старания без гонки** (`rewards-without-race`) - Как отмечать шаги ребёнка и не делать семейное внимание платой за баллы.
- **Чтение с разговором** (`reading-conversation`) - Три вида вопросов к тексту: найти, объяснить, заметить неизвестное.
- **Цифровые привычки всей семьи** (`digital-family-agreement`) - Понятные правила устройств, покупок и помощи, которые относятся и к взрослым.
- **Как проверить заметку вместе** (`verify-information`) - Автор, дата, исходные данные и честная степень уверенности вместо угадывания по оформлению.
- **ИИ в домашке: помощник с проверкой** (`ai-homework-helper`) - Как получать подсказки и примеры, сохраняя собственную работу ребёнка и его данные.
- **Как пользоваться ответами родителю** (`parent-answer-key`) - Разбор помогает найти место ошибки и выбрать подсказку, а не продиктовать чистовик.
- **Подготовка к проверочной маленькими шагами** (`exam-practice-plan`) - Разделяем тему, формат и ошибку; выбираем следующий учебный шаг без ярлыка «способный».

В каждой статье практические предложения отличены по формулировке от краткой опоры на источник. В вопросах убеждения и пропаганды используются вымышленные школьные примеры. Цель - проверка утверждений, самостоятельность суждения и уважение к людям, без навязывания заранее выбранного политического вывода. Доверие к сообщению не предлагается определять по стране, национальности автора или знакомому логотипу.

Статья о программах объясняет различие между общей европейской рамкой компетенций и национальными или региональными учебными программами. Единой программы школьных предметов ЕС по классам не заявлено.

## Контракт данных для интерфейса и сервера

Статья:

- `audience: "parent"` у всех материалов.
- `title`, `summary`, `category`, `minutes` подходят для плитки.
- `sections[]` содержит `title`, `text` и иногда `bullets[]`.
- `activity` содержит заголовок и пошаговую практику.
- `sources[]` находится внизу модели статьи: `title` и `url`.
- `sourceCheckedAt` фиксирует дату текущей проверки ссылок.

Курс:

- `levels`, `minAge` и `maxAge` дают ориентиры подбора.
- `modules[].theory` - массив абзацев, `mission` - строка практического задания.
- У вопроса `type: "choice"`; `answer` - **индекс массива options с нуля, записанный строкой**. Например, `"1"` означает второй вариант.
- `hint` - одна подсказка, `solution` - массив абзацев разбора.
- Ответы и решения находятся только в серверном JSON. Детская сериализация должна исключать `answer` и `solution`; статическая раздача исходного JSON недопустима.
- Родительский доступ и утечка ключей через API этим изменением не проверялись.

## Грамота и критерий завершения

В `completion` зафиксирован критерий успешного модуля: верные ответы на все 3 вопроса, то есть `passingPercent: 100` и `scoreScope: "module"`. Сервер сохраняет успешность каждого модуля.

В каждом курсе 4 модуля по 3 вопроса. Грамота выдаётся только после успешного прохождения всех 4 модулей. Внутри модуля 3 верных ответа из 3 дают `3 / 3 × 100 = 100%`. Можно разбирать ошибки, исправлять ответы и повторять проверки без ограничения. Это учебная практика, не школьный экзамен; повторные попытки не понижают уже полученное достижение.

Грамота называется **«Электронная грамота Луми»**. Она отмечает успешное выполнение встроенных проверок всех модулей конкретного курса. Это не государственный документ, не аккредитация и не подтверждение внешней квалификации. Метаданные согласованы с серверным контрактом; проверка реализации выдачи грамоты и хранения прогресса выполняется на уровне приложения отдельно.

## Время

Для статей `minutes` рассчитано как количество слов в заголовке, описании и разделах / 150, округлённое вверх, минимум 2 минуты. Практика в расчёт не включена. Это оценка интерфейса, не норматив скорости чтения.

Для курса использована авторская оценка по 10 минут на модуль: 4 × 10 = 40 минут. В сумме 6 × 40 = 240 минут, разделяемых на отдельные занятия. Это оценка объёма, не требование сидеть без перерыва и не условие получения грамоты.

## Выполненная проверка

Локальная проверка Node.js завершилась с `ok: true`:

- 12 статей, 48 непустых разделов, 12 практик.
- 6 курсов, 24 модуля, 72 вопроса.
- 114 уникальных идентификаторов между статьями, курсами, модулями и вопросами.
- Все уровни - целые числа от 0 до 11, повторов уровней внутри записи нет.
- Все варианты ответа непустые и не повторяются в пределах вопроса.
- Все ключи - допустимые строковые индексы с нуля.
- Подсказки и объяснения непустые.
- 20 уникальных HTTPS-ссылок на проверенные первичные источники.
- Отдельно пересчитаны четыре числовых сценария: 150 × 4 = 600, 17 × 4 = 68, 1 + 2 = 3, 2 × 3 = 6.
- В новых JSON нет длинного тире.

Повторить основную структурную проверку из папки LUMI:

```powershell
@'
import fs from 'node:fs';
import assert from 'node:assert/strict';
const { articles } = JSON.parse(fs.readFileSync('content/parent-articles.json', 'utf8'));
const { courses } = JSON.parse(fs.readFileSync('content/courses.json', 'utf8'));
const ids = new Set();
function unique(id) {
  assert(!ids.has(id), 'Повтор ID: ' + id);
  ids.add(id);
}
for (const article of articles) {
  unique(article.id);
  assert(article.sections.every(s => s.title && s.text));
  assert(article.activity.steps.length >= 3);
}
let questions = 0;
for (const course of courses) {
  unique(course.id);
  assert.equal(course.completion.passingPercent, 100);
  assert.equal(course.completion.scoreScope, 'module');
  assert.equal(course.completion.allModulesRequired, true);
  assert.equal(course.completion.retryAllowed, true);
  assert.equal(course.modules.length, 4);
  for (const module of course.modules) {
    unique(module.id);
    assert.equal(module.quiz.length, 3);
    assert(module.theory.length && module.mission);
    for (const q of module.quiz) {
      unique(q.id);
      assert(q.type === 'choice');
      assert(/^(0|[1-9][0-9]*)$/.test(q.answer));
      assert(Number(q.answer) < q.options.length);
      assert(q.hint && q.solution.length && q.solution.every(Boolean));
      questions += 1;
    }
  }
}
assert.equal(articles.length, 12);
assert.equal(courses.length, 6);
assert.equal(questions, 72);
console.log({ ok: true, articles: articles.length, courses: courses.length, questions, uniqueIds: ids.size });
'@ | node --input-type=module
```

Это проверка структуры, числовых примеров и внутренней согласованности. Независимая педагогическая экспертиза, испытание эффективности на детях и проверка доступности интерфейса этим этапом не проведены.
